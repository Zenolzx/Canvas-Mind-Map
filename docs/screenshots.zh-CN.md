# README 截图清单

## 当前已准备的图片

README 已接入四张 1600 × 900 PNG，分别为中英文的浅色概览与深色写作界面，位于 `docs/images/`。来自当前 Composer 组件的浏览器展示环境，使用虚构的文章大纲；不是概念设计图，也不包含私人资料。展示环境替代了宿主文件接口，因此不应把它们称为完整 Obsidian 实机验收截图。

复现方式：先运行 `node scripts/verify-composer-browser.cjs` 构建展示页，再运行 `node scripts/capture-readme.cjs`。示例内容和组件截图由该脚本统一生成，不使用旧版壁纸或生成式插画。

### 拍摄规格

1. 统一到 1600 × 900，或 1920 × 1080。PNG，100% 系统缩放优先，不用手机拍屏，不放大低分辨率截图。
2. 每个画面分别切换插件的英语和简体中文；内容也相应翻译。中英文展示同一结构，不要一个版本拥挤、另一个版本空白。
3. 使用“从想法到一篇好文章”等可公开的真实示例。一级分支可为“发现问题 / 组织结构 / 展开写作 / 打磨与分享”。正文要有具体句子，不使用无意义占位符。
4. 关闭多余标签、开发者工具、通知与无关浮层。鼠标移到空白边缘，等自动保存完成，等悬浮提示消失再拍。
5. 可保留干净的 Obsidian 标题栏以体现宿主环境；也可只截插件内容区，但所有图片采用同一裁切规则。不要露出私人文件名、用户名路径或同步信息。
6. 检查根节点、最外侧分支和正文没有被截断；不要为了塞下全部节点而缩到无法阅读。写作图中看清结构和正文比展示大树更重要。

### 可选短动图

10–15 秒即可：新建同级节点 → 输入标题 → 添加子节点 → 打开正文 → 创建笔记。另一个选题是把灵感箱中的想法拖入脑图。每条只展示一个流程，无需添加花哨转场。README 静态图先完成，动图不是发布前置条件。

把原始 PNG 给维护者即可，不必额外加 Logo、边框、阴影或宣传文字。替换 `docs/images/` 对应文件时，README 路径无需修改。
